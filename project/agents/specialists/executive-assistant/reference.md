## Priority Management Framework

### The Quadrant System

```
              URGENT
                │
    Q1: DO NOW │ Q2: SCHEDULE
    (Crisis)   │ (Strategic)
               │
IMPORTANT ─────┼───── NOT IMPORTANT
               │
    Q3: DELEGATE│ Q4: ELIMINATE
    (Interrupts)│ (Time wasters)
               │
            NOT URGENT
```

### Priority Scoring

When the principal has >10 items competing for attention, score each:

| Factor | Weight | Scoring |
|--------|--------|---------|
| Revenue impact | 3x | Direct revenue = 3, Indirect = 2, None = 0 |
| Deadline proximity | 2x | Today = 3, This week = 2, This month = 1 |
| People blocked | 2x | External people = 3, Team = 2, Just principal = 1 |
| Reversibility | 1x | Irreversible = 3, Hard to reverse = 2, Easy = 1 |
| Uniqueness | 1x | Only principal can do = 3, Others could help = 1 |

Present as: "Top 3 priorities today, in order, with reasoning."

### Delegation Decision Tree

```
Can someone else do this?
├─ No (requires principal's authority/knowledge/relationships) → Principal does it
├─ Yes, but it's sensitive/strategic → Principal does it with EA support
├─ Yes, team member is qualified → Delegate
│  ├─ Clear deadline? → Assign with date
│  ├─ No deadline? → Assign, EA follows up in [timeframe]
│  └─ Needs context? → EA provides brief + assigns
└─ Yes, but no one available → EA handles directly or flags capacity issue
```

### Delegation Communication Template

When suggesting delegation to the principal:

```markdown
**Suggestion: Delegate [task] to [person]**

- **Why them:** [Their capability/bandwidth/relevance]
- **What they need:** [Context to provide, resources, authority level]
- **Deadline:** [When it needs to be done]
- **Check-in:** [When EA will follow up to ensure completion]
- **If it goes wrong:** [Backup plan / what principal needs to know]
```

## Multi-Calendar Coordination

### Rules for Scheduling Across Organizations

1. **Principal's calendar is truth** — Always check their calendar first
2. **Buffer rules apply across all calendars** — 15 min minimum between meetings
3. **Timezone protocol:**
   - Store all times in principal's home timezone internally
   - Present in recipient's timezone in external communications
   - Include both timezones for cross-timezone meetings
4. **Conflict resolution priority:**
   - Board/investor meetings (highest)
   - Client meetings (revenue)
   - Internal leadership meetings
   - Team meetings
   - Optional meetings (lowest)

### Complex Scheduling Protocol (5+ parties)

1. Determine the immovable attendees (must be there)
2. Check their availability first
3. Find overlapping windows
4. If no overlap exists, propose splitting the meeting or doing async
5. Present top 3 options to principal
6. On approval, send invitations with clear agenda and duration
7. Confirm within 24 hours; if no response, send one follow-up
8. If scheduling fails after 2 attempts, escalate to principal with status

### Calendar Hygiene (Weekly Review)

Every week (Friday or Monday), review the calendar for:
- Meetings without agendas (flag to owners)
- Back-to-back stretches >3 hours (suggest breaks)
- Recurring meetings with poor attendance (suggest cancellation)
- Meetings that should be emails (flag diplomatically)
- Focus time blocks getting consistently overridden (protect them)

## Confidentiality Protocol

### Classification Levels

| Level | Examples | Who Can See |
|-------|----------|------------|
| **Open** | Public announcements, general business info | Anyone |
| **Internal** | Team updates, project status, basic financials | Team only |
| **Confidential** | Strategy, compensation, personnel issues, deals in progress | Principal + specified people |
| **Restricted** | Legal matters, M&A discussions, termination plans | Principal only |

### Handling Rules

- Never mention restricted information in shared channels (Slack, group email, etc.)
- When in doubt about classification, treat as Confidential
- If someone asks about confidential info, respond: "I'll check with [principal] and get back to you"
- Don't store confidential info in shared docs — use private channels or encrypted storage
- In meeting notes, mark confidential sections clearly: "[CONFIDENTIAL — not for distribution]"

### Personnel Matters

When the principal discusses HR issues (hiring, firing, performance, compensation):
- Handle with zero information leakage
- Never hint to team members about pending decisions
- If someone asks about an upcoming decision, respond neutrally
- Destroy/archive notes appropriately after resolution
- Never summarize personnel discussions in shared briefings

## Board Meeting Protocol

### Timeline

| Weeks Before | Action |
|---|---|
| 4 weeks | Confirm date, send save-the-date, begin metric collection |
| 3 weeks | Draft board deck outline, request inputs from team |
| 2 weeks | First draft of deck + CEO update, send pre-reads to board |
| 1 week | Final deck, prepare Q&A anticipation doc, logistics confirmed |
| Day before | Final review, print materials (if in-person), confirm attendance |
| Day of | Technical setup, materials ready, note-taker assigned |
| Day after | Send minutes + action items within 24 hours |

### Board Deck Standard Structure

1. **Executive Summary** (1 slide) — 3 key highlights, 1 key concern
2. **Key Metrics** (2-3 slides) — Revenue, growth, burn, runway, KPIs
3. **Progress vs. Plan** (2 slides) — What was committed, what was delivered
4. **Challenges & Risks** (1-2 slides) — Be honest. Boards hate surprises.
5. **Strategic Discussion** (2-3 slides) — Topics requiring board input
6. **Asks** (1 slide) — What you need from the board (approvals, intros, advice)
7. **Appendix** — Detailed financials, cohort data, etc. (reference only)

### Board Member Management

For each board member, maintain a profile:
- Investment thesis (why they invested)
- Expertise areas (what to tap them for)
- Pet peeves (what frustrates them)
- Question patterns (what they always ask about)
- Preferred communication style
- Last 1:1 date and topics
- Open action items from previous meetings

## Travel Protocol

### Booking Preferences

Capture once and remember:
- Preferred airline(s) and loyalty programs
- Seat preference (window/aisle, position)
- Hotel chain preferences and loyalty programs
- Car rental preferences
- Dietary restrictions (for meal bookings)
- Budget thresholds (when to ask vs. just book)
- Red-eye tolerance
- Layover tolerance (max connection time)

### Pre-Trip Checklist

- [ ] Flights booked and confirmed
- [ ] Hotel booked and confirmed
- [ ] Ground transport arranged (airport → hotel, hotel → meetings)
- [ ] All meetings scheduled with correct timezone
- [ ] Restaurant reservations made (if applicable)
- [ ] Documents printed/prepared for meetings
- [ ] Travel brief compiled and sent to principal
- [ ] Emergency contacts compiled
- [ ] Expense tracking system ready (category per trip)
- [ ] Return prep: who covers what while principal is away

### During-Trip Support

- Monitor for flight changes/delays (proactive alert)
- Be available for urgent rescheduling
- Handle email triage with awareness of timezone/availability
- Adjust schedules if meetings run long
- Track expenses as they're submitted

## Communication Style Matching

### Learning the Principal's Voice

Observe patterns in:
- **Sentence length** — Short and punchy? Or longer, detailed?
- **Formality** — "Hey!" vs "Dear [Name],"
- **Sign-off** — "Best," / "Thanks," / "Cheers," / name only
- **Emoji/exclamation** — Do they use them? With whom?
- **Response length** — Brief replier? Or thorough?
- **Directness** — Get to the point? Or build context first?

### Adapting by Audience

The principal likely writes differently to:
- Board members (more formal, data-driven)
- Clients (professional but warm)
- Team (casual, direct)
- Friends/personal (most casual)

Match the appropriate register when drafting for each audience.

### When to Flag Tone Concerns

If a received communication has concerning tone:
- "Dana's email reads more terse than usual — might be frustrated about the delay"
- "Client used ALL CAPS in subject — could be escalating"
- "Investor asked for 'a quick call' — in my experience this is rarely quick"

Surface tone signals without over-interpreting. The principal knows their relationships.

## Proactive Behaviors

Things the EA should do without being asked:

1. **Monday:** Quick week-ahead preview ("Here's what's coming")
2. **Before board meetings:** Start prep 4 weeks out
3. **After travel:** Compile expense report from receipts
4. **When patterns emerge:** "You've cancelled this recurring meeting 3 times — should we kill it?"
5. **When something's overdue:** "Heads up — you promised [person] [thing] by [date]. It's [days] past."
6. **When capacity is maxed:** "You have no free time this week. Something needs to move."
7. **When relationships go cold:** "You haven't spoken to [important contact] in 45 days."
8. **Before end of quarter:** Compile summary of progress vs. goals
